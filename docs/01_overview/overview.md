まずは通信の全体像を把握しておきましょう。
図1はTLS 1.3通信の全体像を示したものです。

図1は、[RFC 9846 §2（Protocol Overview）](https://datatracker.ietf.org/doc/html/rfc9846#section-2)のFigure 1から本書で扱う範囲を抜粋して図にしたものです。

*TLS 1.3通信の全体像*

この中で、クライアントのClientHelloからFinishedまでのやり取りをTLSハンドシェイクと呼びます。ハンドシェイクの後に、クライアントとサーバーはHTTPやMQTTなどのアプリケーションデータをやり取りします。

## どこから暗号化されるのか

図1に暗号化されている箇所の表記を重ねたものが図3です。

図3から分かるように、平文で流れるのは、ClientHelloとServerHelloの2つだけです（後方互換のために送信されるchange_cipher_specを除けば）。この2つを交換した時点で暗号化通信の準備が整うため、EncryptedExtensions以降はすべて暗号化されます。サーバー証明書も署名も、経路上からは見えません。

![暗号化されている箇所](./img/9.png)

*通信で暗号化されている箇所*

TLS 1.2では、暗号スイートの選択や鍵交換に必要な情報を段階的にやり取りするため、TLS 1.3よりも1往復多くの通信が必要でした。TLS 1.3では、クライアントが最初のメッセージで鍵共有に必要な情報を送信することで、ハンドシェイクを効率化し、通信に必要な往復回数を削減しています。

## 本物の通信を覗いてみる

図だけではイメージしにくいので、実際に通信でやり取りされているバイト列を覗いてみましょう。
ここでは、Go標準ライブラリのTLSクライアントである`crypto/tls`を利用し、その下でやり取りされているバイト列をすべて表示してみます。

::: code-group

```go [cmd/main.go]
package main

import (
	"crypto/tls"
	"encoding/hex"
	"fmt"
	"io"
	"net"
)

type dumpConn struct {
	net.Conn
}

func (c *dumpConn) Write(p []byte) (int, error) {
	fmt.Printf("--> send %d bytes\n", len(p))
	fmt.Print(hex.Dump(p))
	fmt.Println()
	return c.Conn.Write(p)
}

func (c *dumpConn) Read(p []byte) (int, error) {
	n, err := c.Conn.Read(p)
	if n > 0 {
		fmt.Printf("<-- recv %d bytes\n", n)
		fmt.Print(hex.Dump(p[:n]))
		fmt.Println()
	}
	return n, err
}

func main() {
	raw, err := net.Dial("tcp", "example.com:443")
	if err != nil {
		panic(err)
	}
	conn := tls.Client(&dumpConn{Conn: raw}, &tls.Config{
		ServerName: "example.com",
		MinVersion: tls.VersionTLS13,
		MaxVersion: tls.VersionTLS13,
	})
	defer conn.Close()
	fmt.Fprintf(conn, "GET / HTTP/1.1\r\nHost: example.com\r\nConnection: close\r\n\r\n")
	io.Copy(io.Discard, conn)
}
```
